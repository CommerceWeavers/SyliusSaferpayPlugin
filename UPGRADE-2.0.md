# UPGRADE FROM `1.x` TO `2.0`

Version 2.0 supports **Sylius 2.x only** (PHP ^8.2, Symfony ^6.4 || ^7.4). Stay on the `1.x` releases for Sylius 1.x.
The payment integration is still based on Payum.

## Requirements

1. The plugin now requires `sylius/core-bundle`, `sylius/payum-bundle` and `sylius/ui-bundle` `^2.0` instead of
   the whole `sylius/sylius` package.
1. `sylius/calendar`, `ramsey/uuid`, `enshrined/svg-sanitize` and `php-http/message-factory` are no longer required.
   `symfony/clock` and `symfony/uid` are used instead.
1. `symfony/webpack-encore-bundle` is no longer required by the plugin.

## Templates and assets

1. The admin and shop UI is now integrated via Sylius Twig Hooks:
    * the Saferpay gateway fields are rendered in the
      `sylius_admin.payment_method.{create,update}.content.form.sections.gateway_configuration.saferpay` hooks,
    * the payment method logos are rendered in the
      `sylius_shop.shared.form.select_payment.payment.choice.details` hook.
1. Remove the copied `templates/bundles/SyliusShopBundle/Checkout/SelectPayment/_choice.html.twig` override from your
   application - it is no longer used.
1. Remove the `cw-saferpay-admin-entry` webpack entry (`assets/admin/entry.js`) - the plugin no longer ships admin assets.
1. All templates were moved and renamed to snake_case under `templates/admin/` and `templates/shop/`; the old
   `templates/Admin/**` templates and the `sylius_ui` template events
   (`commerce_weavers_saferpay.admin.payment_method.configure_payment_methods*`) were removed.
1. The `Admin/Order/Show/Payment/_refundTransition.html.twig` block was removed - Sylius 2 renders the refund button
   for order payments itself.

## Routing

1. The transaction log details page (`commerce_weavers_saferpay_admin_transaction_log_show`, same name and path) is now
   generated by the `commerce_weavers_saferpay.transaction_log` resource route and rendered with the Sylius 2 CRUD
   templates; the custom route definition with its own template was removed.
1. Make sure your application imports the Sylius Payum shop routes
   (`@SyliusPayumBundle/Resources/config/routing/integrations/sylius_shop.yaml`).

## State machine

1. Refunds are processed on the `workflow.sylius_payment.transition.refund` event (Symfony Workflow, the Sylius 2
   default). The winzou `before refund` callback is still registered when `winzou/state-machine-bundle` is installed.
1. Refunds are only sent to Saferpay for payments whose gateway factory is `saferpay`.

## Services

1. Plugin services are private now, except Payum actions and
   `CommerceWeavers\SyliusSaferpayPlugin\Processor\RefundProcessorInterface` (used by the winzou callback).
1. `Sylius\Calendar\Provider\DateTimeProviderInterface` was replaced with `Symfony\Component\Clock\ClockInterface` in the
   constructors of all `CommerceWeavers\SyliusSaferpayPlugin\TransactionLog\EventListener\*` listeners.
1. `CommerceWeavers\SyliusSaferpayPlugin\Client\SaferpayClientInterface::getTerminal()` and
   `CommerceWeavers\SyliusSaferpayPlugin\Resolver\SaferpayApiBaseUrlResolverInterface` now accept
   `Sylius\Component\Payment\Model\GatewayConfigInterface` instead of `Payum\Core\Model\GatewayConfigInterface`.
1. The `CommerceWeavers\SyliusSaferpayPlugin\Payment\Event\Payment*` event classes are now `final readonly`.
1. `CommerceWeavers\SyliusSaferpayPlugin\Controller\Action\PrepareAssertAction` gets a `Symfony\Component\Clock\ClockInterface`
   as 8th constructor argument. When the payment is being processed by a webhook, it waits `$retryDelayInSeconds`
   (default 0.2) between attempts instead of retrying immediately; `$maxAttempts` defaults to 50 (was 100).
1. `CommerceWeavers\SyliusSaferpayPlugin\Processor\SaferpayPaymentProcessor::lock()` now uses one lock per payment
   (`cw_saferpay_payment_processing_<paymentId>`) instead of a single global `payment_processing` lock, and always
   releases it.
1. `TransactionLog::$occurredAt` is now a `DateTimeImmutable` (Doctrine type `datetime_immutable`);
   `TransactionLogInterface::getOccurredAt()` returns `DateTimeImmutable` instead of `?DateTimeInterface`.
   Run the plugin migrations (`Version20261120120000`).
1. Failed payment assertions are now logged in the transaction log as "Payment assertion failed" (was
   "PaymentAssertionFailed"), in line with the other log entries. Existing log entries are not changed.
1. The plugin no longer configures the application's `main` Monolog handler; it only registers the `saferpay`
   channel and its `saferpay.log` handler.

## Gateway configuration encryption

Sylius 2 encrypts gateway configurations, but it skips gateways that use Payum (`usePayum = true`). Saferpay gateways
are Payum-based, so their configuration (incl. the API password) is stored as before.
